## 摘要
视觉Transformer（ViTs）在计算机视觉中表现出色，但参数数量庞大且计算复杂度呈二次增长，严重限制了其在资源受限的边缘硬件上的部署。虽然递归权重共享减少了参数数量，而令牌合并缓解了计算和内存瓶颈，但将这两种范式整合在一起且无需昂贵的重新训练并非易事，这一交叉领域在很大程度上仍未被探索。我们提出了MergeOver，一种将令牌合并（ToMe）集成到递归权重共享的切片递归Transformer（SReT）中的训练后方法。通过Unmerge跟踪栈、约束安全的合并率调整以及跨空间置换的同步令牌质量跟踪，MergeOver解决了该集成的空间和合并约束。我们进一步采用了一种逐阶段单次调度，在每个阶段的第一块执行令牌缩减，并在其后续递归迭代中保持固定的序列长度。在ImageNet-1K上进行基准测试，我们选择的配置将top-1准确率降低了1.47个百分点。在GPU上，批次大小为1和16时，峰值激活内存分别减少了37.3%和38.4%，而吞吐量在批次大小为1时下降了21.7%，但在批次大小为16时增加了21.7%。在Raspberry Pi 5（ARM CPU）上，批次大小为1和16时，延迟分别降低了2.4%和17.6%。这些结果表明，MergeOver可以在无需重新训练的情况下，恢复递归权重共享引入的部分吞吐量和内存成本，并为将令牌合并与层次化递归Transformer相结合提供了基线。

## Abstract
Vision Transformers (ViTs) demonstrate exceptional performance in computer vision but suffer from large parameter counts and quadratic computational complexity, severely limiting their deployment on resource-constrained edge hardware. While recursive weight-sharing reduces parameter counts and token merging mitigates computational and memory bottlenecks, integrating these two paradigms without costly retraining is non-trivial, leaving this intersection largely unexplored. We propose MergeOver, a post-training approach that integrates Token Merging (ToMe) into the recursively weight-shared Sliced Recursive Transformer (SReT). Through an Unmerge tracking stack, constraint-safe merge-rate adjustment, and synchronised token-mass tracking across spatial permutations, MergeOver resolves the spatial and merging constraints of this integration. We further employ a stage-wise single-shot schedule that performs token reduction at the first block of each stage and maintains a fixed sequence length throughout its subsequent recursive iterations. Benchmarked on ImageNet-1K, our selected configuration reduces top-1 accuracy by 1.47 percentage points. On the GPU, it reduces peak activation memory by 37.3% and 38.4% at batch sizes 1 and 16, while throughput decreases by 21.7% at batch size 1 but increases by 21.7% at batch size 16. On a Raspberry Pi 5 (ARM CPU), it reduces latency by 2.4% and 17.6% at batch sizes 1 and 16. These results show that MergeOver can recover a meaningful part of the throughput and memory cost that recursive weight-sharing introduces, without retraining, and provides a baseline for combining token merging with hierarchical recursive transformers.

## 二、论文提出的方法论

### 2.1 核心思想

MergeOver 的核心思想是：将 ToMe 的令牌合并机制以**训练后**方式集成到 SReT 的递归层次化架构中，在不重新训练的前提下减少序列长度，从而降低计算开销和峰值激活内存，同时通过一系列机制解决二者结合时产生的结构不兼容问题。

### 2.2 关键技术细节

- **三个结构不兼容问题及解决方案**：

  | 问题 | 解决方案 |
  |------|----------|
  | 令牌合并破坏 SReT 层间卷积池化所需的二维空间网格结构 | **Unmerge 跟踪栈**：合并时存储对应的 Unmerge 函数，在进入卷积池化层前按严格逆序恢复原始序列长度 |
  | 无约束合并违反 SReT 切片分组自注意力（SGA）的组大小整除性约束 | **约束安全的合并率调整**：合并数 r 必须满足组数整除性、至少每组一个令牌、且不超过二分匹配上限 |
  | SReT 的空间置换会破坏 ToMe 按比例注意力的令牌质量跟踪 | **同步令牌质量跟踪**：将质量张量（mass tensor）与特征序列并行地通过相同的置换和逆置换函数，保持二者对齐 |

- **合并约束公式**：
  - (N − r) mod g = 0（序列长度须能被 LCM 整除）
  - N − r ≥ g（每组至少一个令牌，g = LCM(g₁, g₂)）
  - r ≤ ⌊N/2⌋（二分匹配中一组最多合并半数令牌）

- **令牌质量跟踪机制**：
  - 初始化质量张量为全 1，随前向传播和合并操作不断更新。
  - BSM 匹配时使用**未加权的 Key 矩阵**计算相似度，确保合并决策纯由语义相似性驱动，防止高累积质量令牌主导匹配。
  - 合并时使用**质量加权平均**：先按质量加权特征，合并后再除以更新后的质量，避免单补丁令牌和多补丁令牌在合并中影响力失衡。

- **令牌缩减调度策略**（共四种）：
  - **全局常量调度**（r_const）：每层合并固定数量的令牌。
  - **全局线性调度**（r_lin）：首层合并 2r 个令牌，线性递减至最后一层为 0。
  - **阶段式指数调度**（ρ_exp, α）：每阶段开始时请求较高缩减率，随后按指数衰减。
  - **阶段式单次调度**（ρ_shot）：仅在每阶段第一个块执行令牌缩减，后续递归迭代保持固定序列长度。

- **流程概述**：
  1. 图像经过卷积嵌入生成 784 个令牌。
  2. 在三个阶段中，每个阶段第一个 Transformer 块执行令牌合并（按约束调整后的 安全速率）。
  3. 进入层间卷积池化前，通过 Unmerge 栈恢复原始空间尺寸。
  4. 最终经过全局平均池化和线性分类器输出结果。

## 六、论文的主要结论与发现

1. **可行性与有效性**：MergeOver 成功证明了在无需重新训练的前提下，将令牌合并集成到递归层次化 ViT 中是可行的。

2. **选定的最佳配置**（ρ_shot = 0.25，阶段式单次调度）：
   - Top-1 准确率仅下降 1.47 个百分点（从 77.39% 降至 75.92%），满足精度保持标准。
   - 计算量从 1.91 GFLOPs 降至 1.49 GFLOPs（-22.0%）。
   - **GPU（BS=16）**：吞吐量提升 21.7%，PAM 降低 38.4%。
   - **GPU（BS=1）**：吞吐量下降 21.7%，PAM 降低 37.3%。
   - **x86 CPU（BS=16）**：延迟降低 30.0%，吞吐量提升 42.9%。
   - **ARM CPU（BS=16）**：延迟降低 17.6%，吞吐量提升 21.4%。
   - **CPU 单流（BS=1）**：x86 延迟降低 17.9%，ARM 仅降低 2.4%。

3. **关键发现**：
   - 调度策略的选择显著影响硬件收益：阶段式调度优于全局调度，单次调度优于指数调度。
   - GPU 上存在批次大小交叉现象：BS 较小时 MergeOver 反而降低吞吐量（开销未摊薄），BS ≥ 8 后才转为正收益。
   - CPU 上所有批次大小均受益，但 ARM 单流推理的收益非常有限。
   - PAM 主要由阶段初始缩减率决定，而非调度形状本身。
   - FLOPs 不能很好地预测硬件性能（如 ρ_exp=0.40 虽然 FLOPs 更低但吞吐提升不如 ρ_shot=0.40，因为 FLOPs 未计入 BSM 匹配、质量跟踪和 Unmerge 操作的开销）。

4. **落地意义**：MergeOver 是递归层次化 Transformer 结合令牌合并的**训练后压缩基线**，证明了无需重训练也能恢复递归权重共享引入的部分吞吐量和内存成本。

4. **内存测量不可比对**：
   - GPU PAM 用 CUDA allocator 测量（精确的激活内存）。
   - CPU 内存用 ΔRSS（进程常驻内存变化）测量，包含分配器缓存、后端工作区等，不纯是激活内存。
   - 两者不可直接比较，且 ΔRSS 行为在批次大小和调度间不一致，论文也承认无法用这些数据严格排序。

5. **FLOPs 估计不完整**：thop 库的 FLOPs 计算没有包含 BSM 匹配、质量跟踪、序列操作和 Unmerge 跟踪的开销，因此不能作为硬件性能的可靠预测指标。

6. **缺少低层优化与剖析**：未进行内核级性能剖析或优化，平台间和批次间的性能差异原因仍停留在假设层面（如“开销摊薄”假说未被严格验证）。

7. **未与其他高效架构对比**：没有与常规高效 ViT（MobileViT、EfficientViT、FastViT 等）进行端到端对比，因此无法断言 MergeOver 在绝对意义上的优越性。

8. **单流边缘场景收益有限**：在 Raspberry Pi 5 上 BS=1 的单流推理场景中，延迟仅降低 2.4%，几乎可以忽略不计。这表明 MergeOver 引入的 BSM 匹配、Unmerge 栈管理等额外开销，在低并行度的边缘设备上难以被摊薄，其适用范围更适合批处理或多流并行场景。

9. **对训练过程的影响未讨论**：虽然 MergeOver 是训练后方法，但合并操作会影响令牌的语义分布，进而可能影响后续层（尤其是蒸馏模型）的行为。论文未讨论这种影响是否会在更深层累积、是否会对模型鲁棒性（如对抗样本）产生副作用。

## 九、总结与展望

总体而言，MergeOver 是一篇定位清晰、实现完整、实验覆盖面较广的训练后压缩工作。它的核心贡献不在于提出全新的注意力机制或架构，而在于**打通了递归权重共享与令牌合并两条此前独立发展的研究路线**，并以工程化的方式解决了二者结合时的结构不兼容问题。

从学术价值看，该工作为“训练后加速递归 Transformer”提供了第一个可行基线，并为后续研究留下了若干明确方向：

- **调度策略的自适应化**：当前 4 种调度均为手工设计，若能根据输入图像的复杂度或硬件实时状态动态决定合并位置和缩减率，可能进一步提升收益。
- **更大模型与更多任务的验证**：SReT-Small/Base、检测/分割任务上的表现仍是空白。
- **与其他压缩手段的叠加**：MergeOver 与量化、剪枝、蒸馏等方法的正交组合值得探索。
- **更精细的硬件协同设计**：若能在 BSM 匹配、Unmerge 重排等核心操作上做内核级优化，BS=1 的边缘场景也有望受益。

从应用角度看，MergeOver 证明了“已部署的递归 ViT 无需重训即可加速”这一实用价值，对于边缘 AI 产品的快速迭代具有现实意义。但受限于实验规模（单模型、单数据集）和度量不统一的问题，其结论的普适性仍需更多证据支撑。整体而言，这是一篇**动机明确、技术扎实、实验充分但深度有限**的论文，值得对高效 ViT 和边缘推理感兴趣的读者精读。
