## 摘要
剪枝是提高LLM效率的一种有前景的方法。现有的静态结构化剪枝方法对硬件友好，并能带来实际的吞吐量提升，但其与输入无关的计算分配在激进稀疏度下往往导致显著的精度下降。最近的动态稀疏方法通过根据单个输入调整计算来提升质量保持，但它们大多局限于粗粒度的结构决策，并且在实际推理场景中的实际加速仍然具有挑战性。为了应对这些挑战，我们提出了WIDE，这是首个为预填充（prefill）和解码（decode）场景设计的端到端可微分的令牌级动态宽度剪枝框架。WIDE通过允许每个令牌动态选择注意力头组和FFN通道组来实现细粒度的计算分配，将动态剪枝从层级别决策扩展到神经元块级别的粒度。通过两阶段训练流程，WIDE学习了有效的令牌级稀疏执行模式，并实现了比现有方法更好的质量保持。为了使这种细粒度的动态剪枝变得实用，我们进一步提出了一种剪枝-内核协同设计框架，将动态稀疏加速分解为掩码重排序、硬件无关的块级跳跃和硬件相关的块内跳跃，从而在不同粒度上实现高效执行。在50%稀疏度下，与最先进的动态深度剪枝相比，WIDE在仅校准设置下提供了55.1%的性能提升。在预填充和解码推理工作负载下，WIDE实现了接近理论的内核级加速，预填充最高达到1.98倍，解码最高达到4.95倍，以及1.68倍和1.55倍的端到端加速。我们的代码可在 https://github.com/EIT-NLP/LLM-Pruning/tree/main/WIDE 获取。

## Abstract
Pruning is a promising approach for improving the efficiency of LLMs. Existing static structured pruning methods are hardware-friendly and can deliver practical throughput gains, but their input-agnostic computation allocation often causes substantial accuracy degradation under aggressive sparsity. Recent dynamic sparsity methods improve quality retention by adapting computation to individual inputs, yet they remain largely limited to coarse-grained structural decisions and their practical acceleration under real-world inference scenarios remains challenging. To address these challenges, we present WIDE, the first end-to-end differentiable token-level dynamic width pruning framework designed for both prefill and decode scenarios. WIDE enables fine-grained computation allocation by allowing each token to dynamically select attention-head groups and FFN-channel groups, extending dynamic pruning beyond layer-level decisions to neuron-block-level granularity. Through a two-stage training pipeline, WIDE learns effective token-wise sparse execution patterns and achieves substantially better quality retention than existing approaches. To make such fine-grained dynamic pruning practical, we further propose a pruning--kernel co-design framework that decomposes dynamic sparsity acceleration into mask reordering, hardware-agnostic block-level skipping, and hardware-dependent intra-block skipping, enabling efficient execution across different granularities. At 50% sparsity, WIDE provides 55.1% performance boost when compared to the state-of-the-art dynamic depth pruning under calibration-only settings. Under prefill and decoding inference workloads, WIDE achieves close-to-theoretical kernel-level speedups of up to 1.98x for prefill and 4.95x for decoding, as well as 1.68x and 1.55x end-to-end acceleration. Our code is available at https://github.com/EIT-NLP/LLM-Pruning/tree/main/WIDE.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：随着 LLM 规模扩大和 Agent 系统复杂度提升，高效推理成为关键挑战。除系统级优化外，模型剪枝（pruning）是提升推理效率的重要模型级手段。
- **现有静态剪枝的问题**：静态结构化剪枝（如删除整层、注意力/FFN 子层、权重行/列等）硬件友好、易于部署，但与输入无关的固定剪枝决策在激进稀疏度下会造成显著精度损失。
- **现有动态剪枝的问题**：动态剪枝通过轻量路由器按 token 分配计算，但大多局限于粗粒度深度决策（如跳过整层或子层），无法对需要部分计算的 token 提供精细容量控制；同时，细粒度动态稀疏带来的不规则执行模式难以转化为实际推理加速。
- **核心研究问题**：
  1. 动态剪枝能否超越粗粒度深度决策，实现更精细的计算分配并保持更好的质量？
  2. 这种细粒度动态决策能否被高效执行，带来真正的端到端加速？
- **整体含义**：作者提出首个端到端可微分的 token 级动态宽度剪枝框架 WIDE，将剪枝粒度推进到注意力头组和 FFN 通道组（神经元块级），并通过剪枝-内核协同设计实现实际加速，推动动态结构化剪枝的前沿。

## 2. 方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 核心思想
- 每个 token 独立选择细粒度的计算模块：GQA 对齐的注意力头组和可配置的 FFN 通道组。
- 采用两阶段训练（路由训练 + 可选 LoRA 恢复）学习 token 级稀疏执行模式。
- 通过剪枝-内核协同设计（掩码重排序 + 多粒度块跳跃）将动态稀疏转化为高效的 GPU 执行，同时支持预填充和解码场景。

### 2.2 剪枝单元设计
- **注意力剪枝单元**：以注意力头为最小原子，按 GQA 头组大小 G（= Hq/Hk × d）进行分组；掩码 Mattn ∈ {0,1}^{B×Tq×Hk}，避免对 Wk/Wv 剪枝导致 KV 缓存驱逐，并兼容 GQA 解码优化（如 XQA）。
- **FFN 剪枝单元**：以 GEMM 平铺尺寸 G（∈{16,32,64,...}）为组大小，对中间维度 D' 进行连续分组；统一掩码 Mffn ∈ {0,1}^{B×T×(D'/G)}，覆盖 Up/Gate 投影的输出特征和 Down 投影的输入特征。
- **路由组件**：使用瓶颈结构（W1∈R^{D×r}, W2∈R^{r×2NG}），输出每个组的二分类决策（执行/跳过）；训练时用 Gumbel-Softmax（硬采样），推理时用 argmax。

### 2.3 两阶段训练
1. **路由器训练**：冻结所有非路由参数，仅用校准数据优化路由组件。
2. **LoRA 恢复（可选）**：在所有线性模块上加入 LoRA，进一步恢复精度。
3. **损失函数**：
   \( L = L_{\text{LM}} + \alpha \left( S - \frac{1}{2N}\sum_{i=1}^N \left[ \left(1-\frac{1}{|M^i_{\text{attn}}|}\sum M^i_{\text{attn}}\right) + \left(1-\frac{1}{|M^i_{\text{ffn}}|}\sum M^i_{\text{ffn}}\right)\right] \right) \)
   其中 S 为目标稀疏度，α 为稀疏损失权重。

### 2.4 推理期加速框架（剪枝-内核协同设计）
- **动机**：朴素 gather-scatter 实现存在设备到主机同步、额外内存移动和存储开销（论文给出理论分析：N 轴/K 轴剪枝朴素实现需要 O(pMNK) 的中间存储）。
- **掩码重排序预处理**：对每个路由组 g，将掩码按 M 维度降序排序，使活跃行聚集成连续前缀，并生成行索引 I，将不规则 token 路由转化为 CTA 级规则性（除每个组至多一个边界 tile）。
- **多粒度跳跃谓词**：
  - ℓ=0：硬件无关的 CTA 早期退出（跳过完全非活跃的 [BM, G] 块）；
  - ℓ=1：硬件相关的 A 加载包跳跃（如 cp.async 行加载、TMA gather4）；
  - ℓ=2：硬件相关的 MMA 片段跳跃（如 wmma、wgmma、tcgen05.mma）。
- **三类定制内核**：
  - **GEMM-MN**：用于 Q/Up/Gate 投影（N 轴剪枝）和动态深度剪枝（NG=1 特例）；
  - **GEMM-K**：用于 O/Down 投影（K 轴剪枝），按 K 组局部流水线处理，组间原子加回写；
  - **Attention**：融合 FlashAttention 的在线 softmax 和 Q 侧多粒度跳跃，支持因果/非因果掩码。
- 所有内核保持稠密风格平铺流水线，条件性抑制加载和 MMA，避免破坏流水线阶段同步。

## 6. 主要结论与发现

- **质量保持优势**：
  - 校准-only 下，25% 稀疏度时 WIDE（G=32）在 Llama3.1-8B 上保留 97.92% 稠密精度；50% 稀疏度时平均准确率比最强非 WIDE 静态方法提升 8.80 点（8B）和 8.97 点（3B）。
  - LoRA 恢复后，WIDE 在 50% 稀疏度下仍保持约 90% 性能保留率，优于 SkipGPT 约 3~4 点，优于 DDP 约 10 点。
- **加速效果**：
  - 50% 稀疏度下，预填充内核级加速最高 1.98×，解码内核级加速最高 4.95×；
  - 端到端加速：预填充 1.68×，解码 1.55×；
  - 在 0% 稀疏度时，WIDE（G≤128）保持 98.60% 稠密吞吐，路由和优化内核额外开销极低。
- **核内实现效率**：CuTe 内核相比朴素 gather-scatter，在 GEMM-N/K 上可减少约 1000 倍峰值内存，吞吐提升约 200 倍。
- **路由行为具有语义感知**：FFN 路由器倾向于保留语义内容词（如名词、动词），跳过虚词（如冠词），注意力层在不同层呈现非均匀稀疏分布（平均注意力稀疏 66.2%，FFN 28.5%），与静态剪枝的层敏感性研究一致，但由 token 条件化路由产生。
- **组大小影响**：较大的组大小更利于内核效率（GEMM-K 在 G>128 接近理想加速），但较小组大小（G=32）通常获得更高精度；注意力 GQA 对齐设置对解码加速至关重要。

## 7. 优点

- **提出首个 token 级动态宽度剪枝框架**：将动态剪枝从层/子层粒度推进到注意力头组和 FFN 通道组粒度，实现更精细的计算分配。
- **端到端可微分训练**：无需额外强化学习或离散优化，通过 Gumbel-Softmax 和可微掩码端到端学习路由决策。
- **剪枝-内核协同设计**：系统化解决动态稀疏的工程障碍（设备到主机同步、不规则 gather-scatter 开销），提出掩码重排序 + 多粒度谓词跳跃的统一框架，使细粒度动态稀疏能获得接近理论加速。
- **同时覆盖预填充和解码**：设计 GEMM-MN/G/EMM-K/Attention 三类内核适配不同场景，并考虑 GQA 兼容性。
- **理论分析扎实**：附录给出朴素 gather-scatter 实现的通信/存储复杂度分析，并用实验验证优化内核的巨大优势。
- **实验充分且对比公平**：覆盖多模型、多稀疏度、多组大小，统一校准数据和 LoRA 恢复设置，并与多个代表性静态/动态方法对比。
- **开放代码**：提供可复现的代码仓库。

## 8. 不足与局限

- **实验规模有限**：仅在 8B 和 3B 模型上验证，未测试更大规模（如 70B）或 MoE 架构的适用性；推理实验主要在 RTX 5090（sm120）上进行，其他架构（A100/H100）上的泛化性未充分展示。
- **训练成本未详细报告**：未说明 10k 步训练的实际耗时和能耗，两个阶段可能带来较高训练成本。
- **组大小-精度-加速权衡未完全量化**：虽然给出了不同组大小的精度和内核速度，但缺乏联合 Pareto 优化分析，实际部署时如何自动选择组大小未给出明确指导。
- **路由器额外开销未完全消除**：推理图中路由执行、掩码排序、零初始化等额外操作仍占解码延迟约 29.1%，论文承认这些开销限制了理论加速。
- **均匀稀疏约束下性能下降**：当强制注意力与 FFN 等比例稀疏时，WIDE 精度下降明显（校准-only 下 G=128 平均精度仅 50.99%），说明模型偏好非均匀分配，可能在某些必须均匀分配的场景中受限。
- **路由行为分析较定性**：语义感知结论基于少量案例可视化，缺乏量化统计（如按词性统计跳过程度）。
- **依赖高级 GPU 特性**：块内跳跃依赖 TMA、tcgen05 等较新硬件特性，对旧 GPU 支持不足；论文提到 Triton/Tilelang 仅支持 CTA 级跳跃，灵活性受限。
- **未与最新的系统级协同方法（如 FlashAttention-4、CUDA Agent 等）进行直接比较**，端到端加速对比主要基于自身基线。
