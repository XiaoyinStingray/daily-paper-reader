## 摘要
低精度优化器状态方法通常针对稠密Adam风格的一阶和二阶矩进行设计和评估。内存高效优化器偏离了这一设定：Adafactor对二阶矩进行分解，CAME添加了分解置信状态，而APOLLO在投影梯度空间中维护统计量。因此，等量的状态重建误差可能根据状态拓扑和更新语义导致不同的更新误差。我们首先在语言模型预训练的优化器状态轨迹中刻画了这种异质性。然后，我们引入了自适应对数空间（AL）量化，这是一种针对非负状态的逐块表示，它逐块调整非零范围，并强制执行精确零不变量$q = 0 \Leftrightarrow x = 0$。AL8和AL16与独立的符号动量编码以及特定于状态的精度选择相结合，而不是对每个状态采用单一策略。在总计214.7 GPU小时的96次运行中，我们评估了AdamW、Adafactor、CAME和APOLLO路径中的稠密、分解、置信和投影状态。在20K步TinyLlama-1.1B预训练基准上，采用AL8二阶矩和均匀8位动量的AdamW配置达到72.90的困惑度，相比之下，FP32 AdamW为72.48，8位动态量化基线为73.54，同时将测得的优化器状态存储从8392.7 MiB减少到2119.2 MiB。CAME展现了不同的精度机制：将其非负状态提升到AL16恢复了86.16的困惑度，而全精度参考为86.68，而全AL8达到90.19。一个100K步GPT-2实验进一步表明，在评估设置中，拓扑感知的参数保护将量化Adafactor的后期损失差距从+0.1185降低到+0.0159。这些结果支持对优化器量化的状态和拓扑感知视图。

## Abstract
Low-precision optimizer-state methods are commonly designed and evaluated for dense Adam-style first and second moments. Memory-efficient optimizers depart from this setting: Adafactor factorizes second moments, CAME adds factored confidence states, and APOLLO maintains statistics in a projected gradient space. Consequently, an equal amount of state reconstruction error can induce different update errors depending on state topology and update semantics. We first characterize this heterogeneity in optimizer-state traces from language model pre-training. We then introduce Adaptive Log-Space (AL) quantization, a block-wise representation for non-negative states that adapts its nonzero range per block and enforces the exact-zero invariant $q = 0 \Leftrightarrow x = 0$. AL8 and AL16 are combined with independent signed-momentum encodings and state-specific precision choices rather than a single policy for every state.   Across 96 runs totaling 214.7 GPU-hours, we evaluate dense, factored, confidence, and projected states in AdamW, Adafactor, CAME, and APOLLO paths. On a 20K-step TinyLlama-1.1B pre-training benchmark, an AdamW configuration with AL8 second moments and uniform 8-bit momentum reaches 72.90 perplexity, compared with 72.48 for FP32 AdamW and 73.54 for an 8-bit dynamic-quantization baseline, while reducing measured optimizer-state storage from 8392.7 to 2119.2 MiB. CAME exposes a different precision regime: promoting its non-negative states to AL16 recovers 86.16 perplexity versus 86.68 for the full-precision reference, whereas all-AL8 reaches 90.19. A 100K-step GPT-2 experiment further shows that topology-aware parameter protection reduces the late-loss gap of quantized Adafactor from +0.1185 to +0.0159 in the evaluated setup. These results support a state- and topology-aware view of optimizer quantization.

## 一、核心问题与研究动机

优化器状态（optimizer states）是大模型训练中内存开销的重要组成部分。以 Adam 为例，每个参数需要维护一阶矩和二阶矩两个状态，以 FP32 存储时，辅助值的数量可达参数数量的两倍。现有的低精度优化器状态方法（如 block-wise 8-bit 量化）大多围绕**稠密 Adam 风格状态**设计和评估，但这一抽象对新一代内存高效优化器并不完备：

- **Adafactor** 将矩阵二阶矩分解为行/列统计量（factored state）；
- **CAME** 在分解基础上额外加入置信状态（confidence state）；
- **APOLLO** 在投影梯度空间中维护统计量，再导出缩放因子作用于原始梯度。

这些优化器的状态不仅在**规模**上不同，更关键的是**误差传播方式**存在结构性差异：一个小的状态扰动可能在分解重建中扩散到整行/整列，或通过反向平方根、置信调制等算子被放大，也可能落在数值不敏感区域而被忽略。因此，**等量的重建误差在不同状态拓扑和更新语义下可能产生截然不同的更新误差**。本文的核心问题是：当优化器状态量化超越稠密 Adam 状态时，会发生什么变化？以及如何设计一种能够适应这些异质性的量化方案？

## 二、方法论

### 2.1 Adaptive Log-Space (AL) 量化

针对非负优化器状态，作者提出 **自适应对数空间量化（Adaptive Log-Space Quantization，简称 AL）**，核心思想是**按块（block-wise）适应非零数值范围**，并**保留精确零码**。

**关键要点：**

- **块自适应对数区间**：对每个块中非零元素，计算其对数（以 2 为底）的最小值 ℓmin 和最大值 ℓmax，形成一个块局部观测区间 [ℓmin, ℓmax]，而非使用固定的全局对数范围。
- **精确零不变量**：量化码本中将码 0 专门保留给精确零元素，非零元素映射到剩下的码，从而严格满足:
  `q = 0 ⇔ x = 0`
  这防止了两个方向的歧义：非零值不会被量化为零（避免反向平方根放大误差），真正的零值也不会被重建为小正数（避免给休眠参数赋予虚假的历史）。
- **AL8 与 AL16**：AL8 使用 256 个码（1 个精确零 + 255 个非零码）；AL16 使用 65,536 个码（1 个精确零 + 65,535 个非零码）。
- **元数据开销**：每块存储两个 FP32 元数据（ℓmin 和 Δℓ），单位元素存储成本约为：`c ≈ precision (1或2字节) + 8/B`。

### 2.2 状态特定精度与动量编码

- **非负状态**（V 二阶矩、C 置信状态）使用 AL 作为主要表示，根据状态敏感性和内存预算选择 AL8、AL16 或全精度。
- **符号动量状态**（M，带正负号）使用基于均匀量化的 8-bit 有符号编码（UF8），实验表明在测试配置下 UF8 比动态映射有更低的重建误差和更新漂移。
- **CAME 置信状态精度独立配置**：与二阶矩精度解耦，因为二者在更新算子中扮演不同角色。

### 2.3 拓扑感知的参数保护（G0/G1 分组策略）

G0 为默认策略，不加特殊保护；G1 将一维张量、偏置、归一化参数、token 嵌入和语言模型头分离出来，以全精度存储其优化器状态，其余张量保留低精度路径。这是粗粒度的语义分组策略。

### 2.4 更新域误差度量

论文引入了**相对更新误差（relative update error）**：

`E_upd = ||U(Ŝt, Gt) − U(St, Gt)||₂ / (||U(St, Gt)||₂ + ε)`

其中 U 是优化器更新算子。该指标直接衡量量化对**实际更新**的影响，而非只看状态重建误差，因为二者未必成比例。

## 六、主要结论与发现

### 6.1 核心结论

**为稠密 Adam 状态设计的统一低比特量化策略，不能直接迁移到分解、置信和投影状态上**。有效的低精度优化器设计应区分三个维度——**状态表示、状态拓扑和更新语义**，没有单一量化器在所有评估路径上统一最优。

### 6.2 具体实验结果

1. **AdamW**：UF8 动量 + AL8 二阶矩达到 **72.90 PPL**，逼近 FP32（72.48），同时优于 8 位动态量化基线（73.54）；优化器状态存储从 8392.7 MiB 降至 2119.2 MiB（减少约 75%），吞吐从 2502 提升至 2960 tokens/s。
2. **CAME**：全部 AL8 有显著质量差距（90.19 vs 参考 86.68）；将非负状态提升到 AL16 可恢复至 **86.16**，几乎追平 FP32 参考，且绝对状态内存增量仅约 2.3 MiB。说明 CAME 对非负状态精度远敏感于 AdamW。
3. **Adafactor**：FP32 参考仅 3.6 MiB 状态，量化路径主要检验拓扑敏感性。块大小 256 优于 2048；G1 保护策略在 20K 网格中一致更好。100K 长时程中，G1 + B=256 将后期损失差距从 **+0.1185 降至 +0.0159**。
4. **APOLLO**：UF8 + AL8 达到 75.24 PPL（参考 74.68），降低 384 MiB 状态，但吞吐量在报告实现中低于参考。
5. **精确零不变量**：对稠密块代价几乎为零（0.079% vs 0.078% 状态误差），但在稀疏（90% 零）场景中，无保留变体的无裁剪更新误差可超 100%，而保留设计仅 0.122%。
6. **自适应范围 vs 固定范围**：固定对数范围无法同时适应窄/中/宽三种分布，自适应逐块范围可将更新误差保持在 1% 以下。

## 七、方法亮点与优点

1. **精确零不变量**：`q=0 ⇔ x=0` 的双向约束是对现有文献的重要补充——Li et al. 只考虑了"小正值被量化为零"的危险，本文额外处理了"真零被重建为正数"的问题，对稀疏嵌入场景尤其重要。
2. **状态感知的精度分配**：不再是一刀切的量化策略，而是根据状态类型（非负统计量 vs 有符号动量）、状态规模（V 的 AL8 大存储 vs C 的 AL16 低成本）和更新算子敏感性做独立精度选择。CAME 实验中 2.3 MiB 的额外精度投入带来 4 PPL 的改善，展示了这种分配的价值。
3. **更新域误差度量**：引入 E_upd 作为诊断指标，在算子层面度量量化保真度，而非只看状态重建误差——这解决了一个实际痛点：重建误差大小与训练质量的好坏不直接对应。
4. **三轴分析框架**：将状态表示、状态拓扑、更新语义三者分开，并以四种优化器路径（稠密/分解/置信/投影）作为天然实验变量，框架清晰、有概括力。
5. **严格的实现验证**：分离参考算法对齐和 CUDA 数值一致性测试（171 PASS / 4 WARN），并对 WARN 项做了归因（factorized atomicAdd 累加顺序），方法严谨透明。
6. **块粒度与元数据权衡的定量分析**：给出了 AL8/AL16 的单位存储公式（1+8/B 或 2+8/B bits/element），并在合成 5K 步 EMA 上做了块大小性能帕累托扫描。

## 八、不足与局限性

1. **规模与任务覆盖有限**：仅评估了 1.1B（20K 步）和 124M（100K 步）两个架构，WikiText-103 单一语料，单设备训练设置。无法确认向更大模型、多语料、多卡分布式训练中的迁移性。
2. **单种子端到端实验**：最终困惑度/损失差距是**测量值而非不确定性估计**，缺乏多种子重复验证。论文明确承认这一点，但这对实验的统计说服力是实质限制。
3. **G1 分组策略耦合**：同时保护一维张量、偏置、归一化参数、token 嵌入和 LM head，无法区分究竟是哪一类张量的保护带来了 Adafactor 的改善。100K 实验缺少 G1 × B=2048 条件，无法估计长时程下分组与块大小的交互效应。
4. **CAME 全 AL8 的质量差距未被完全解决**：all-AL8 CAME 有 3.51 PPL 的明显差距，虽然提升精度可弥补，但这恰好说明 AL8 并非对所有非负状态都足够——这在某种程度上削弱了 AL8 作为通用 8-bit 方案的竞争力。
5. **内存与速度统计的不完整性**：优化器状态字节数不等于总训练内存；峰值内存来自 PyTorch 分配计数器，部分 20K 运行的峰值用 1K 代理运行近似；吞吐量仅反映单 GPU/单实现，不能推广到其他硬件栈。
6. **合成受控分布的代表性问题**：合成分布（对数正态）无法穷举真实优化器状态的分布形态，更新域误差是诊断性指标，不构成最终任务质量的保证。
7. **APOLLO 路径的吞吐量反而下降**：本文配置在 APOLLO 路径上吞吐为 2077 tokens/s，低于参考的 2331 tokens/s——虽然状态内存降低，但实际速度优势未体现，工程实用性存疑。
8. **G1 分组在小模型上的代价**：保护嵌入和 LM head 在绝对内存上代价不大，但在更大词表/更大嵌入的模型中，这种保护的存储成本会显著上升，文中未讨论这一扩展性问题。
